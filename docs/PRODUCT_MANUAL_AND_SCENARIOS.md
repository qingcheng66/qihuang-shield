## 一、 这个项目究竟为了解决什么问题？（三大核心痛点）

中医药博大精深，但在现实生活与医疗实践中，存在三大长期困扰行业与大众的“硬伤痛点”：

### 痛点 1：处方流转中的“隐形杀手”——配伍禁忌与超量毒性
*   **现实困境**：
    *   中药有几千种，古人以血的教训总结了严苛的配伍红线——**“十八反、十九畏”**。例如：**甘草绝不可同用甘遂/大戟/芫花**，一旦混用会产生剧烈毒性，诱发肠坏死与心律失常；**细辛药典极量仅 3g**（“细辛不过钱”），超量会引发中枢神经麻痹与呼吸衰竭。
    *   在大量基层药房、社区诊所及中药房实习环境中，每天面对繁杂的书写体或打印处方，审方全靠药工**人工肉眼逐味核对**，极易因疲劳导致疏漏，造成严重医疗事故。
*   🎯 **岐黄盾的解法**：**【中药处方 AI 毫秒级安全安检机】**  
    手机对准纸质处方拍一张照，系统 0.2 秒内通过 PaddleOCR 结构化提取药味与剂量，经 Java 规则引擎交叉比对，秒级拦截十八反、十九畏与超量毒药，为发药抓药筑起一道永不疲劳的安全刹车皮。

---

### 痛点 2：大众盲目养生，“越补越虚、越吃越偏”
*   **现实困境**：
    *   当下青年与中老年人普遍热衷于喝中药养生茶、炖滋补药膳、自购中成药（如阿胶、六味地黄丸）。
    *   但中医讲究**“九种体质，辨证施膳”**。如果一个本身就是**“湿热体质”**（满面油光、舌红苔黄厚腻、口苦便秘）的人，盲目跟风吃人参、鹿茸、生姜羊肉汤去“大补”，结果适得其反，导致狂冒痘、严重口腔溃疡与上火。
    *   普通大众不可能每天为了喝一杯养生茶，专门去三甲中医院挂号排队半天找医生问“我是什么体质”。
*   🎯 **岐黄盾的解法**：**【装在每个人口袋里的中医体质轻测助手】**  
    晨起或饭前，手机伸出舌头自拍一张。轻量深度学习算法自动分析舌色（淡白/红/绛红）与苔质（薄白/黄厚腻/剥脱），生成九维体质雷达图，告诉你“当前偏湿热”，并给出明明白白的食谱：“今天别喝姜茶，喝杯赤小豆薏仁水，按一按小腿上的阴陵泉穴”。

---

### 痛点 3：中医药古籍文献晦涩，查阅循证门槛极高
*   **现实困境**：
    *   中医药医学生和爱好者查阅《神农本草经》《本草纲目》《中国药典》时，文字晦涩，方剂与药材之间的相互关系极其复杂，缺乏直观的可视化工具。
*   🎯 **岐黄盾的解法**：**【动态交互式方剂本草知识图谱】**  
    将 500+ 味中药、200+ 首名方的归经、性味、君臣佐使与禁忌关系转化为力导向图谱。相克药材之间连有触目惊心的**红色相克虚线**，点击药材即刻下钻展开古籍与现代药理毒性机制。

## 三、 三大核心业务使用场景与操作指引（Step-by-Step）

### 场景 1：【中药房 / 实习生抓药审方：30 秒配伍快速安检】

```text
[拿到患者处方单] ──> [手机对准拍照] ──> [0.2秒完成OCR] ──> [看红黄蓝灯] ──> [安全抓药/联系医生]
```

1. **打开系统**：手机扫码或点击桌面图标启动“岐黄盾”（全屏 PWA 模式，无浏览器杂乱边框）；
2. **拍照上传**：进入【处方配伍审查】，对准纸质处方（手写或打印单）拍摄，前端 Canvas 自动完成本地等比压缩；
3. **毫秒级字符识别**：Python 后端 PaddleOCR 自动提取出处方中的全部中药味与剂量（如“生甘草 6g、甘遂 3g、细辛 5g”）；
4. **实时风险判定与应对**：
   * 🔴 **红色高危拦截**：若出现十八反（如甘草反甘遂），屏幕立刻弹出红色警报与《本草纲目》原文，**药工立刻停发，退回医生更正**；
   * 🟡 **黄色剂量超标**：若细辛超量（5g > 3g），提示存在挥发油麻痹呼吸中枢毒性；
   * 🔵 **蓝色特殊煎法**：提示制附子“必须先煎 30~60 分钟”；
   * 🟢 **绿色通过**：方剂配伍七情严整，放心抓药调配。

---

### 场景 2：【普通上班族 / 居家养生：10 秒晨起望舌辨体质】

```text
[晨起自然光下] ──> [前置镜头伸舌头] ──> [对准绿色取景框] ──> [生成雷达图] ──> [遵循食疗与穴位]
```

1. **唤起相机**：点击【数字望舌与体质辨识】，系统申请调用前置摄像头；
2. **辅助引导取景**：屏幕中央浮现出带有微光的“中医舌形椭圆取景框”，用户将舌头自然伸入框内；
3. **视觉特征量化提取**：
   * YOLOv8 神经网络秒级扣除嘴唇与阴影干扰；
   * CIELAB 色彩空间提取舌质颜色（淡红/红/绛红）；
   * 计算机视觉计算舌苔覆盖度与厚薄（薄白/黄厚腻）；
4. **生成个人健康雷达卡片**：
   * 输出《中医九种体质倾向雷达图》（如：湿热质 88 分、气虚质 30 分）；
   * 给出针对性的调理建议：“今日体内湿热偏重，推荐饮用赤小豆薏米荷叶茶，忌吃油炸辛辣，建议按揉小腿阴陵泉穴”。

---

### 场景 3：【答辩现场 / PC 宽屏控制台：本草方剂知识图谱探索】

```text
[电脑宽屏打开网页] ──> [进入知识图谱大屏] ──> [鼠标拖拽漫游] ──> [点击中药下钻看药典考据]
```

1. **进入大屏**：评审专家在电脑浏览器打开控制台，切换至【方剂本草知识图谱】；
2. **物理力导向漫游**：
   * 屏幕呈现深色科技风的星系图谱，节点由中药（绿）、名方（赤）、归经（金）、功效（青）组成；
   * 鼠标可任意按住拖拽节点，滚轮无级缩放；
   * 甘草与甘遂、乌头与半夏之间拉出醒目的**红色相克虚线**；
3. **古籍考据下钻**：点击图谱中的任一药材（如“黄芪”），右侧或下方抽屉立即展开《中国药典》性味归经与李东垣《脾胃论》中补中益气汤的君臣佐使专论。

## 四、 竞赛答辩标准话术库（评委提问标准回答）

### 提问 1：这个项目到底有什么实际价值，不是玩具吗？
> **答辩话术**：  
> “报告评委老师，我们的核心价值在于**‘将医疗事故防范关口前移’**。传统药房全靠人工肉眼防范十八反十九畏，每天几百张方子难免百密一疏。岐黄盾就像一道数字化安全阀，0.2 秒完成拍照排查，把可能致死的配伍相克与有毒中药超量彻底拦截在发药之前。同时，它让老百姓不花一分钱就能随时知道自己的中医体质，不再盲目乱吃补药，真正做到了‘中医药服务健康中国’。”

### 提问 2：你们这算不算‘非法行医’或‘无证开方’？
> **答辩话术**：  
> “报告老师，我们在立项之初就严格遵循了国家医疗法规红线：**我们坚决不越界做任何临床疾病诊断，也坚决不开具任何治疗处方**。  
> 我们的定位极其明确：① 对医生处方做**安全规则审查（核对是否触犯法定禁忌）**；② 对大众做**生活调养与体质科普（给出日常药膳与作息建议）**。系统界面与报告均有强制科普声明，完全合规。”

### 提问 3：为什么不直接调用外部大模型，要自己做架构？
> **答辩话术**：  
> “第三方大模型存在两大致命缺陷：一是高延迟与额度限制，答辩现场一旦断网或限流就直接瘫痪；二是容易产生‘模型幻觉’，在人命关天的用药安全上胡说八道。  
> 因此我们采用 **Java + Python 异构微服务**：底层用严谨的 Java 集合碰撞保证配伍禁忌 100% 毫秒级命中、零误报；AI 感知用本地轻量 OCR 和计算机视觉模型，**零调用费、零外网依赖，安全性和稳定性完全自主可控**。”
